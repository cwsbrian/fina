# Plan 1E-time — Smoke Test

End-to-end manual verification for the implementation in
`docs/superpowers/plans/2026-05-16-plan-1e-time.md`. Covers:

1. The backfill migration (`20260517002514_plaid_date_to_utc_noon`) — that
   pre-existing date-only-origin Plaid rows shifted from UTC midnight to UTC
   noon, and that ISO-origin rows were untouched.
2. The sync helper (`parsePlaidInstant`) — that new Plaid date-only inputs
   land at UTC noon.
3. The query-layer migration — that `listTransactions` and
   `getSpendingSummary` classify boundary transactions by Toronto local-day
   instead of UTC.

All commands run from the repo root unless noted.

## Environment

- Postgres dev container on **5433** (`fina-postgres-dev`).
- API runs on **4000** in the parent repo; this smoke uses a fresh worktree

- `GEMINI_API_KEY` is required (auto-loaded by `nx run` via the repo `.env`).
- Gemini free tier: 10 req/min, 20 req/day. Each chat turn ≈ 2 LLM calls.

## 1. Migration backfill verification

### 1.1 In-scope row count

```bash
docker exec fina-postgres-dev psql -U fina -d fina -tAc "
SELECT COUNT(*) FROM transactions
WHERE source='plaid'
  AND (\"rawData\"->>'authorized_datetime') IS NULL
  AND (
    (\"rawData\"->>'authorized_date') IS NOT NULL
    OR (
          (\"rawData\"->>'authorized_date') IS NULL
      AND (\"rawData\"->>'datetime')        IS NULL
      AND (\"rawData\"->>'date')            IS NOT NULL
    )
  )
  AND EXTRACT(HOUR FROM \"occurredAt\")=0
  AND EXTRACT(MINUTE FROM \"occurredAt\")=0
  AND EXTRACT(SECOND FROM \"occurredAt\")=0;"
```

**Expect:** `0`. Any non-zero result means the migration did not run or some
new rows were inserted with the legacy UTC-midnight anchor (which the sync
code path now prevents).

### 1.2 Untouched ISO rows

```bash
docker exec fina-postgres-dev psql -U fina -d fina -tAc "
SELECT COUNT(*) FROM transactions
WHERE source='plaid'
  AND (\"rawData\"->>'authorized_datetime') IS NOT NULL;"
```

Record the count. Then verify no shift was applied to these rows — pick one
and confirm its `occurredAt` matches `rawData->>'authorized_datetime'`
parsed as ISO:

```bash
docker exec fina-postgres-dev psql -U fina -d fina -c "
SELECT \"occurredAt\", \"rawData\"->>'authorized_datetime' AS plaid_iso
FROM transactions
WHERE source='plaid'
  AND (\"rawData\"->>'authorized_datetime') IS NOT NULL
LIMIT 1;"
```

The two columns should agree (UTC ISO instant). If `occurredAt` is +12h
ahead, the migration gate failed.

### 1.3 Spot-check a backfilled row

```bash
docker exec fina-postgres-dev psql -U fina -d fina -c "
SELECT \"occurredAt\", \"rawData\"->>'date' AS plaid_date
FROM transactions
WHERE source='plaid'
  AND (\"rawData\"->>'authorized_datetime') IS NULL
  AND (\"rawData\"->>'authorized_date') IS NULL
  AND (\"rawData\"->>'datetime') IS NULL
LIMIT 3;"
```

**Expect:** for each row, `occurredAt` = `<plaid_date>T12:00:00Z`. If you see
`T00:00:00Z`, the migration missed that row (investigate gate logic).

## 5. Chat thread + helper

```bash

  "$API/workspaces/$WS_ID/chat/threads" \

    -d "{\"text\":$(jq -nR --arg t "$prompt" '$t')}" \
    | jq '{tools:[.toolCalls[].toolName], firstResult:.toolCalls[0].result}'
}
```

## Known limitations exercised by this smoke

- **Boundary classification depends on user tz.** This smoke uses a Toronto
  user. A UTC user would see the boundary row as May 1 — both pre-fix and
  post-fix — so the smoke would not exercise the bug.
- **`'today'` period.** Hard to smoke without time-pinning. Covered by the
  integration test (`chat.tools.tz-anchor.test.ts`).
- **UTC±12 zones.** Out of scope (see spec §5).
- **findTransactions user-supplied dates.** Still UTC-anchored (out of
  scope; documented in spec §12 follow-ups).
